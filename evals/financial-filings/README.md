# Financial filings eval

A test set for AskMyDoc's answers on financial filings: 20 filings (10-Ks, one 10-Q and two annual reports) and 85 questions. 67 questions have an answer in the filing; 18 ask for something the filing doesn't contain, and the correct response is "not in the document".

Questions are split by filing into 51 working cases (12 filings), used to investigate and tune, and 34 test cases (8 filings), scored once at the end.

## Files

| Path | What it is |
|---|---|
| `cases.json` | The 85 questions with expected answers, evidence text, evidence pages (zero-indexed PDF pages) and notes on every correction. |
| `manifest.json` | The 20 filings: download URL, SHA-256, page count and split. |
| `scoring-rules.md` | How answers are scored, decided before any run. |
| `verification/absence-checks.json` | How each "not in the document" question was confirmed absent. |
| `verification/answer-recomputes.json` | Every calculated answer recomputed from its evidence, with the formula used. |
| `corpus-proposal.md` | The original research that selected these filings and questions. |
| `documents/` | Downloaded PDFs. Not committed. |
| `*.local.json` | Document and chunk IDs from local indexing. Not committed; regenerated by the scripts below. |

## Reproducing

1. Download each PDF in `manifest.json` from its `url` to its `path`, and check the SHA-256.
2. Index them into the local Chroma store:

   ```bash
   .venv/bin/python -m backend.scripts.index_eval_documents \
       --corpus evals/financial-filings/manifest.json \
       --output evals/financial-filings/indexed-documents.local.json
   ```

3. Build the evaluator's case file, which maps each answer's evidence to chunk IDs:

   ```bash
   .venv/bin/python -m backend.scripts.build_eval_cases \
       --proposed evals/financial-filings/cases.json \
       --indexed evals/financial-filings/indexed-documents.local.json \
       --output evals/financial-filings/cases.local.json
   ```

## How the answer key was checked

- Every answerable question's evidence was mapped to the chunks that contain it.
- Every "not in the document" question was checked against the full text of its filing.
- Every calculated answer was recomputed from the filing's own figures.

Corrections keep the original answer in `original_expected_answer` with an `answer_fix_note` explaining the change. Nine expected answers were revised this way: seven corrections, and two inventory-turnover questions that now accept either of two standard calculation methods (listed in `acceptable_answers`). One question's evidence passage was also replaced.
